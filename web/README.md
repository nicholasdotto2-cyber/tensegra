# web: Next.js 16 app

The practice manager app for osteopaths. It lives entirely in `web/`.

## Commands (pnpm)

| Command | What it does |
| --- | --- |
| `pnpm dev` | development server (Turbopack) on 127.0.0.1, with `APP_DEMO_MODE=1` |
| `pnpm build` | production build |
| `pnpm db:migrate` | applies the shim and any missing migration |
| `pnpm db:seed` | creates the demo practice; does nothing if it already exists |
| `pnpm db:reset` | deletes `pglite/` and `files/`, then migrates and seeds; `--empty` skips the seed |
| `pnpm db:unlock` | removes `app.lock` if the process that held it is gone; `--force` removes it even if that process is alive, after you type `SBLOCCA` |
| `pnpm lint` | ESLint |
| `pnpm typecheck` | `next typegen && tsc --noEmit`: generates the route types, then checks the types |
| `pnpm test:unit` | Vitest, `tests/unit` only |
| `pnpm test:db` | Vitest on `tests/db` (tests against PGlite with two practices) |
| `pnpm test:smoke` | starts `next start` on the build (port 3200, data in `.data/smoke`) and checks `/oggi`, a query that uses the extensions, and a PDF. It needs the build: if `.next/BUILD_ID` is missing it stops with "Esegui prima pnpm build." (run pnpm build first) |
| `pnpm test:e2e` | Playwright on `tests/e2e` (port 3100, data in `.data/e2e`, recreated on every run). It needs the build (`pnpm build`) and Chromium: the first time, run `pnpm exec playwright install chromium` |
| `pnpm verify` | lint + typecheck + test:unit + test:db + build + test:smoke: it must pass before every commit |

## Data folder, lock and reset

Data lives in `web/.data/` (you can change it with `APP_DATA_DIR`, but the folder must stay inside `web/`). Inside it: `pglite/` is the database, `files/` holds the uploaded files, and `app.lock` records who is using the folder; `backups/`, `e2e/`, `smoke/` and `test/` belong to other commands.

- **Only one process at a time opens the folder.** `pnpm dev`, `pnpm start`, `db:migrate`, `db:seed` and `db:reset` take the lock before opening the database; `db:unlock` does not take it, it removes it. While the app is running, `db:seed` and `db:reset` wait 5 seconds and then stop with a message, without touching anything.
- **The lock message** gives the PID of the process and the time it started. Close that process first (usually the terminal running `pnpm dev` or `pnpm start`). If the process no longer exists, the next command removes the stale lock by itself, or you can remove it with `pnpm db:unlock`. If the command replies that the process is still running and you are sure it is a leftover, use `pnpm db:unlock --force` and type `SBLOCCA`.
- **`pnpm db:reset` deletes only `pglite/` and `files/`.** It does not touch `backups/`, `e2e/`, `smoke/` or `test/`. It refuses to run if `APP_DATA_DIR` points outside `web/` or at `web/` itself. `pnpm db:reset --empty` recreates the schema without the demo data.
- The `package.json` scripts use the `VAR=1 command` form: it works on Windows too, because `pnpm-workspace.yaml` sets `shellEmulator: true`.

## Next.js 16 changes we rely on

Source: the official Next.js 16 upgrade guide (nextjs.org/docs/app/guides/upgrading/version-16).

1. **`params` and `searchParams` are asynchronous.** In `page`, `layout` and `route` they must be read with `await props.params`; the same goes for `cookies()` and `headers()`. Synchronous access has been removed entirely. The `PageProps<'/path'>` types are generated by `next typegen`.
2. **Turbopack is the default bundler** for both `dev` and `build`: no `--turbopack` flag in the scripts. If a `webpack` config were ever needed, the build would fail unless it runs with `--webpack`.
3. **`next lint` no longer exists** and `next build` does not run the linter. Linting is the `lint` script, which runs ESLint directly (flat config in `eslint.config.mjs`); that is why `verify` calls it separately.
4. **`revalidateTag` takes a second argument** (`revalidateTag('tag', 'max')`). For Server Actions where the user must see the change immediately, there is the new `updateTag`.

Requirements: Node 24.14 or newer, TypeScript 5.1 or newer.

## shadcn/ui with Tailwind v4 changes we rely on

Source: the official shadcn/ui guide for Tailwind v4 (ui.shadcn.com/docs/tailwind-v4) and its changelog.

1. **No `tailwind.config.js`:** in `components.json` the `tailwind.config` field is empty and the theme lives in `src/app/globals.css` (`@theme inline` plus CSS variables in `:root` and `.dark`).
2. **Colors in OKLCH**, no longer HSL; the variables are no longer wrapped in `hsl()`.
3. **Animations with `tw-animate-css`** (`@import "tw-animate-css"`), instead of the deprecated `tailwindcss-animate` plugin.
4. **Components without `forwardRef`:** they use `React.ComponentProps` and have a `data-slot` attribute for styling. Sizes use `size-*` instead of `w-* h-*`.
5. **`cn` is the standard shadcn function** in `src/lib/utils.ts` (clsx + tailwind-merge). The init chose the `base-nova` style (Base UI primitives), the `neutral` base color, and CSS variables on. Notifications use `sonner`; the toast component is deprecated.
